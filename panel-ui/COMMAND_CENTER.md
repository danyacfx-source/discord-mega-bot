# DENDICH Command Center — рабочие функции

Встроенный раздел `/admin#/command-center` и сводка на главной странице.

## Действия
- Задачи Discord: создание, приоритет, статус «В очереди → В работе → Готово», удаление.
- Идеи контента: создание, статус «Черновик → Готово к выпуску → Опубликовано», удаление.
- Поиск по названиям и заметкам; фильтрация по типу.
- Быстрые переходы в существующие разделы: модерация, тикеты, эфиры, медиатека, планировщик, статистика.
- Сводка текущих задач и идей на главной панели.

## Настоящее хранение и права
API: `GET /api/workboard` и `POST /api/workboard` с действиями `create`, `update`, `delete`.
Хранение в **KV базы бота**, ключ `panel.command_center.workboard.v1` (работает с SQLite и PostgreSQL через существующий сервис).
Общий список для всей административной команды, сохраняется между обновлениями и перезапусками. Лимит 120 записей и 2000 символов заметки.

- Права **moderator+**: чтение;
- **admin+**: изменения;
- Авторизация и CSRF — из существующей панели;
- Витрина Showcase не публикует внутренние записи;
- Изменения здесь сами по себе не публикуются в Discord. Для публикаций есть «Планировщик».

## Тесты
```bash
python -m pytest tests/test_workboard.py -q
cd panel-ui && npm ci && npm run build
```
GitHub Actions выполняет Python-тесты, проверяет синхронизацию `dist` и браузерный smoke-тест редактирования записей.

## Деплой
Для Docker: `git pull origin main && docker compose up -d --build`.
Для non-Docker хостинга в коммите присутствует обновлённая папка `app/core/webpanel/dist`.

## Подготовка публикации из задачи или идеи

1. В «Оперативном центре» нажми «В планировщик» рядом с записью. Заголовок перейдёт в заголовок Discord-эмбеда, заметка — в описание.
2. Либо открой «Планировщик» напрямую, выбери запись в выпадающем списке и нажми «Подставить».
3. Проверь текст, **явно выбери канал** и будущую дату/время; нажми «Запланировать», чтобы создать запись в существующем планировщике Discord.

Важно: переход и заполнение черновика **не отправляют сообщение**. После планирования исходная задача/идея остаётся без изменений; статус «Опубликовано» выставляется вручную после фактической публикации. Данные черновика передаются только внутри открытой вкладки и не сохраняются в localStorage или публичной витрине.

На телефоне этот сценарий работает точно так же. Он использует существующий API `/api/schedule` со всеми установленными правилами доступа, проверками и CSRF.
